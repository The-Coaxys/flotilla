# Flotilla M7 — Polish and extras

Governing specification: `docs/superpowers/specs/2026-11-02-flotilla-design.md` §8, §9, §14.

Exit criterion: feature parity with the documented feature set (minus non-goals), a signed
release, auto-update, and the performance HUD reporting real numbers.

## Scope

- **Command palette** with every mode (Global, Commands, Files, Worktrees, Tabs, Conversations),
  keyboard-first, fuzzy matching over daemon-provided indexes, and mode switching inside it.
- **Theme editor:** per-workspace Background/Accent/Highlight per mode with the documented
  sliders, color canvas, swatches, copy-from, save/reset/default; independent terminal palettes;
  per-surface font and size; live application of every change.
- **PiP** always-on-top window for one terminal, chat, run or review surface, plus app-level
  always-on-top.
- **Browser tabs:** WebView2 hosted as a child HWND only when a tab opens, port previews detected
  by the daemon and forwarded over the active transport, HTML previews of worktree files,
  element annotation into chat, and `fl browser` automation behind settings and a per-workspace
  grant. Page content is untrusted.
- **Shared Context:** branch-group root holding `FEATURE.md`, `AGENTS.md`/`CLAUDE.md` and
  `context/`; lazy child creation (`fl worktree ensure-child`); grouped diffs with a repo
  summary; repository-role guidance generated by an optional analysis agent or from a template.
- **Custom commands** and prompt templates at every scope, editable in UI and by `fl`.
- **Auto-update:** signed release manifests, verified download, staged replacement with rollback,
  and update prompts that never interrupt a running turn.
- **Performance HUD:** FPS, frame time, RTT, transport, throughput, memory, toggled by
  Ctrl+Alt+Shift+P, plus release profiling (mimalloc, thin LTO, codegen-units 1, opt-level 3)
  measured against recorded M1/M4 baselines.
- **Keymap editor** backed by `keymap.json`, with conflict detection against terminal keys.
- **Window details:** Snap Layouts correctness, optional Mica/Acrylic tied to theme alpha,
  hover cards, bottom-right toasts, top banner, drop-ring drag-and-drop previews, empty-view
  launcher with tool cards and Recent, sidebar Compact/Detailed styles.
- **Windows toasts** via WinRT with AppUserModelID registration in the installer, delivery
  policies per event class with sounds, click-to-source.

## Execution order

1. Release plumbing: signing keys, manifest, updater with rollback, and CI publishing signed
   artifacts (minisign deferred from M0 lives here).
2. Theme editor and keymap editor (they touch every surface).
3. Palette, PiP, launcher, toasts, hover cards, drag-and-drop.
4. Shared Context, custom commands, grouped diffs.
5. Browser tabs, previews, annotations and automation.
6. Performance HUD and the profiling pass with measured numbers.

## Verification gates

- Each feature exercised in the native client; screenshots or recorded measurements where the
  claim is visual or numeric.
- Updater: a real previous release upgrades to the new one, verifies the signature, and rolls
  back on a tampered package.
- Performance: report measured frame time, memory and throughput on the reference VPS and
  record the environment; no unmeasured claims.
- Windows-only features (toasts, Mica, Snap Layouts, WebView2) verified in the Windows job or
  by the owner on real hardware, and labelled accordingly.
- One final full pass: workspace tests, UI tests on Windows, clippy with warnings denied,
  `cargo fmt --check`, installer self-test, signed release published.

## Evidence

### Slice: native command palette, empty-view launcher, hover cards

Native client only (`crates/client/flotilla`). Every source is a mirror the client already
holds; no new wire calls.

- Palette overlay (`app/palette.rs` model + `app/host_workspace/host_palette.rs` UI): Global,
  Commands, Files, Worktrees, Tabs and Conversations. Ctrl+Shift+K (spec §8.3) and
  Ctrl+Shift+P open Global, Ctrl+Shift+O opens Files; inside, Ctrl+1…6 and Tab/Shift+Tab
  switch modes, ↑/↓ move, Enter runs, Esc closes, and typing re-ranks with a pure fuzzy
  scorer (prefix/word-start/contiguous bonuses, stable ties). Files is sourced from cached
  directory listings only and says so in the footer; Conversations lists the mirror's
  sessions and selects their worktree before opening.
- Actions reuse existing model methods: add project, create worktree, new terminal and close
  tab (daemon `LayoutOp`s), panel toggles, scope selection, open file/document, open chat,
  select terminal tab, run setup/run/teardown scripts and the adaptive Git action.
- Empty-view launcher shows when the scope has no documents, no chat tab and no terminal
  tabs: four tool cards and a Recent list merged from worktree `last_active_ms` and session
  `updated_ms` (bounded, stable on ties).
- Hover cards for project, worktree and session rows after a 400 ms hover delay (single
  timer, no polling), rendered at window level: path, branch, target, dirty/ahead/behind,
  lines, kind; provider, status, seq, permission mode, model for conversations.
- Also installs `flc_ui::input::bind_keys`, which existed but was never registered, so
  text-input editing keys (backspace/delete/enter/escape) now work in every dialog and in
  the palette.
- Tests: fuzzy ranking, mode order/chords/next/prev, Recent ordering and tie stability,
  hover field formatting and line bound, launcher card routes. 65 bin tests pass; clippy
  `-D warnings` and `cargo fmt --check` are clean.
- Live X11 run under Xvfb against the `flsmoke` daemon: palette (Global 24 rows, Files with
  the cached-directory note, Worktrees filtered by "fea"), "Open Chat panel" run from
  Commands, feature-z hover card, launcher after closing the scope's only tab, and New
  terminal from a launcher card. Screenshots: `m7-02-palette-global.png`,
  `m7-05-files-panel.png`, `m7-06-palette-files.png`, `m7-07-palette-worktrees.png`,
  `m7-08-command-typed.png`, `m7-09-command-run.png`, `m7-13-close-tab-command.png`,
  `m7-15-hover-card.png`, `m7-16-launcher.png`, `m7-17-launcher-new-terminal.png` in
  `/srv/super-eng/.shots`.
- Not covered by this slice: theme editor, PiP, browser tabs, Shared Context, custom command
  CRUD, performance HUD, keymap editor. Ctrl+Shift+P currently opens the palette; it is the
  documented PiP key and should move when PiP lands.

### Slice: theme editor, keymap editor, and the Ctrl+Shift+P decision

Native client only (`crates/client/flc-ui`, `flc-terminal`, `flc-shell`, `flc-editor`,
`flotilla`); no daemon or wire change.

**Hotkey collision (decided from spec §8.3).** The spec assigns `Ctrl+Shift+P` to PiP and
`Ctrl+Shift+K` to the palette's Global mode, so the palette no longer answers `Ctrl+Shift+P`.
That chord is now a reserved keymap action (`pip.toggle`, group *Reserved*) whose handler
states in the top banner that PiP lands in its own slice, and whose chord cannot be taken by
any other action. `Ctrl+Shift+,` (Settings) is new; it is listed in the keymap editor like
every other app binding.

- `flc_ui::theme_settings` — modes System/Light/Dark; per-mode Background/Accent/Highlight
  with the documented sliders (Background intensity and alpha, Accent and Highlight
  prominence); resolution into `Theme` tokens (mix + WCAG luminance/contrast with a
  readable-text floor); `SurfaceFonts` (UI/editor/terminal families, editor, terminal-tab,
  right-panel-terminal sizes, chat scale); hex parse/format. Shipped dark defaults resolve to
  the spec's `#27262B` / `#3D8BFD` / `#2D2E33`.
- `flc_ui::theme` — light token set; `Theme` carries the per-surface font fields the editor,
  diff, terminal and chat read.
- `flotilla::settings` — `<config>/Flotilla/settings.json` beside `hosts.json`: a default
  workspace entry, per-workspace overrides keyed by the daemon's workspace id, and the
  per-surface fonts. Writes are atomic (temp file + rename). A corrupt file is reported and
  left untouched; saving refuses until the user explicitly replaces it.
- Terminal palettes stay independent: rendering uses the engine's 269 colors unless the
  workspace's explicit override is on, which replaces only the 16 ANSI cells (cube, greys and
  named defaults stay the engine's). `TerminalViewOptions.palette` feeds the renderer;
  `ShellViewOptions` carries font family/size/palette to every pane.
- Live application: every theme, palette or font edit rebuilds the GPUI `Theme` global and
  refreshes windows; `ShellView::set_presentation` pushes font/size/palette into every live
  terminal, and panel (setup/run/teardown) terminals are sized separately. Editor and diff
  render with the editor font/size, chat text multiplies by the chat scale.
- `flc_ui::keymap` — chord parse/canonical spelling/labels, the effective action table
  (quit, add host, palette Global, palette Files, Settings, reserved PiP), the fixed
  surface-handler table (text input, palette, editor), `keymap.json` load/save with notes for
  unknown actions and bad chords, and conflict checks: no modifier, terminal-owned plain
  `Ctrl+<letter>` (spec §8.3 "the terminal comes first"), another action's chord, or a
  focused surface's handler. Refusal explains the conflict and changes nothing.
- Settings overlay (Theme and Keyboard tabs): mode, Light/Dark palette editing, an 18×8 color
  canvas, 12 swatches, a hex field, the four sliders, copy Light↔Dark, copy from any workspace
  with saved settings, Save / Reset / Set as default; explicit terminal-palette override with
  16 ANSI swatches; per-surface font family chips and size steppers. Keyboard tab lists every
  action with its chord, captures a new chord on click, shows refusals, resets one action or
  all of them, and lists the fixed surface handlers.
- `install_keymap` clears GPUI's bindings and reinstalls the text-input keys, so a rebind
  actually replaces the old chord instead of leaving both alive.
- Tests: theme resolution (spec tokens, system mode, intensity/alpha, prominence), contrast
  math and nudging, hex parse/format, font clamps, JSON tolerance; chord parsing/labels,
  default uniqueness, unmodified/terminal/duplicate/surface refusals, file round-trip and
  corrupt-file reporting, reset; settings store atomic round-trip, per-workspace fallback and
  copy independence, explicit palette override, clamping, corrupt-file preservation; canvas
  and stepper math; terminal palette builder.
- Live X11 run under Xvfb `DISPLAY=:99` against the `flsmoke` daemon (rebuilt at the
  integration tip so both sides speak protocol 0.4): `Ctrl+,` opened the overlay; the Accent
  swatch `#FF8A3D` and the Background hex `#101820` applied live to every surface; the
  terminal-tab size stepper moved 12.5 → 14.5 and the visible terminal text grew; `Save`
  wrote `~/.config/Flotilla/settings.json` (dark background `1054752`/`#101820`, accent
  `16747069`/`#FF8A3D`, `fonts.terminal_size` 14.5); restarting the client brought both the
  theme and the larger terminal font back.
- Keymap editor live: the Command-palette row captured `Ctrl+P` and was refused with
  "Ctrl+P is sent to the terminal while it has focus (spec §8.3: the terminal comes first).",
  leaving the binding unchanged; a second capture succeeded, applied live, and the new chord
  opened the palette. Screenshots: `m7-theme-01-start.png`, `-02-settings-theme.png`,
  `-03-accent-picked.png`, `-04-background-set.png`, `-05-background-hex.png`,
  `-06-scrolled.png`, `-07-font-size.png`, `-08-live-applied.png`, `-09-persisted.png`,
  `-10-keymap.png`, `-11-conflict-refused.png`, `-12-rebound.png`, `-13-rebind-fires.png`
  in `/srv/super-eng/.shots`.
- Base note: the slice sits on `origin/m3-forge` (the lineage that contains the palette
  commit and the protocol the smoke daemon speaks), not on `origin/main`, whose daemon still
  reports protocol 0.2 and rejects this client.
- Not proven live in this pass: `keymap.json` persistence (the save click missed the button;
  load/save/round-trip and corruption handling are unit-tested), a rebind of *Palette: Files*
  specifically (the captured row was the palette Global action), the terminal ANSI override,
  chat scale and editor font, and per-workspace (worktree) theme selection — the live run
  edited the Home/default entry. Remaining in M7: the PiP window itself, Windows Mica tied to
  the alpha slider, and a repeated keymap save with reliable coordinates.

### Slice: measured performance HUD

- `Ctrl+Alt+Shift+P` toggles a native overlay; the keymap editor can rebind it.
  Closing it cancels sampling and stops requesting diagnostic animation frames.
- Frame cadence and mean frame interval come from actual root-view renders;
  these are CPU-side observations, explicitly not GPU execution timing.
- `Sync::terminal_output_bytes` counts output successfully applied by mirrors,
  excluding duplicate records and snapshots. The HUD reports an elapsed-time
  rate across hosts; removing a host cannot create a negative rate.
- Process memory is Linux `VmRSS` or Windows `K32GetProcessMemoryInfo` working
  set. OS queries run on the background executor every 500 ms. Display strings
  are formatted per sample, not per animation frame.
- Native smoke: `cargo build --locked --offline -p flotilla --features linux-x11`,
  launch under Xvfb `DISPLAY=:99`, toggle while a terminal has focus, run a
  4 KiB/50 ms shell-output workload, toggle off and close the client normally.
  `/tmp/flotilla-hud-throughput-continuous.png` captured 11.4 FPS, 87.99 ms
  mean interval, SSH/4 ms RTT, 69.3 KiB/s applied output and 154.0 MiB RSS.
  This was a debug build under software rendering with concurrent builds on
  this VPS, not a release benchmark or a Windows/reference-GPU performance claim.
- Checks: two deterministic sampling/memory-parser tests passed; client,
  sync and UI clippy passed with warnings denied. The Windows memory branch
  requires the Windows build gate. Full release profiling remains open;
  existing release settings already use thin LTO, one codegen unit and level 3.
